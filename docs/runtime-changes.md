# Runtime changes in the vendored ScarletNX

ScarletNX is part of this repository (`third_party/ScarletNX`, from upstream commit 8efbf9c4). The changes below
were patch files before. They are now ordinary commits in the source, and the patch files are deleted. The names
`0001` to `0017` are the old patch numbers. The text says what each change does.

| Change | What it does |
| --- | --- |
| 0001-native-mouse-input | Native mouse input. The mouse is captured and drives the right stick. The left button is ZR and the right button is ZL. A controller input makes the controller the active input. Hold Alt to free the cursor. New settings `mouse_*` (look, sensitivity, vertical sensitivity, invert Y, dead zone offset, curve, overdrive). See `docs/input-analysis.md` and `docs/camera-analysis.md`. |
| 0002-global-red-add-u64 | Shader translation of `RED.E.ADD.64` (a 64-bit add into global memory, size 2 of `RED`). The translator refused it, so one draw in each frame was skipped. The module declares `Int64Atomics`, each global buffer gets a 64-bit view on the same binding (decoration `Aliased`), and the device enables `shaderBufferInt64Atomics`. A device without the feature refuses the program as before. A regression test with a `spirv-val` check is in `tests/shader_direct_regressions.c`. See `docs/shader-analysis.md`. |
| 0009-keyboard-remap | The keyboard map as a setting. The new setting `keyboard_map` (section Keyboard) lists `Button:Key` words, for example `ZL:Q A:F LStickUp:Up`. A button that the text names loses its default keys. A key that the text names belongs only to the buttons named with it. `None` frees a button. A key name is the SDL name, with `_` for a space. Escape, F1 to F12, Pause and Alt are reserved. A word that cannot be read is logged and the map stays. See `docs/input-analysis.md`. |
| 0010-ini-store-256 | The store of the game's `.ini` held 128 keys, and the file already had 129 (the log said `more than 128 keys, renderdoc_frames and those after it are left out`). A key after the 128th was dropped at the read and so erased at the next write of the file. A key that the user added, such as `keyboard_map`, went this way. The limit is now 256. |
| 0012-native-mouse-guest-words | The runtime side of the native mouse look. The setting `mouse_native_address` (0 = off) is the guest address of a 64 bit word (two floats: yaw in radians, pitch in units of the camera arc). The mouse motion is added to it as it arrives, in place of the stick, and the game's code patch `native-mouse-look.pchtxt` takes it. Settings `mouse_native_yaw` (1400) and `mouse_native_pitch` (1000, 500 from `0016`), in millionths for each mouse count, and `mouse_invert_x` and `mouse_invert_y` turn the directions. At most 0.5 of each waits for the game. See `docs/camera-analysis.md`. |
| 0013-imgui-windows | The in-game Dear ImGui windows (plan: `docs/imgui-plan.md`, review: `docs/imgui-review.md`). It is one patch of ten steps that were once separate patches. Dear ImGui 1.93.0 (MIT) is a pinned CPM package (`cmake/dependencies.cmake`, SHA-256 of the release archive). The core and the Vulkan backend (loaded through volk) are built into the renderer and draw a frame over the presented image (`gpu/vk/imgui.c`, `imgui_glue.cpp`). The fonts are read from `fonts/` in the game's data folder (`Roboto-Variable.ttf`, `NotoSansJP-Regular.otf`, from `assets/fonts`), and the built-in font is the fallback. The theme is ImGui's dark theme with the accent `#46478B` and an alpha of 0.94 on the whole window (`imgui_style.cpp`). The window's events go to a queue (`imgui_input.c`, `backend/imgui_sdl.c`) that merges motion and never drops a key, button or focus change, and the frame publishes what the windows want (mouse, keyboard, text, release of the cursor, the input method's place). A menu bar (About, Settings, Mods, Cheats, Debug) shows when the cursor is at the top of the picture, and Alt frees the cursor from the mouse look. The Debug window shows the GPU (NVML, picked by the Vulkan device's UUID), the processor and memory, the frame times, the cost of a frame and the display. The game's software keyboard (the player's name) is a window too: `overlay.c` keeps the state and the ticket protocol, and the old box returns when the windows do not run or the Vulkan backend reports an error. The windows replace the game's old menu (F2, Back, Home, the on-screen menu button), and `legacy_menu` brings it back. New settings `imgui` (default 1), `imgui_test` and `legacy_menu` (default 0), section Debug. While the game presents nothing for a quarter second (a loading interval), the renderer's refresh also runs when the windows have something drawn or an input event waits, so the windows keep updating and the menu bar still opens. |
| 0014-gui-group-icons | The launcher test `gui_sdl_events` wants an icon for the group of each section of `settings.txt`. The sections Mouse (`0001`) and Keyboard (`0009`) had none, so the test failed. Mouse gets the pointer icon and Keyboard the key icon. |
| 0015-imgui-input-test | The host test `imgui_input` for the event queue of the ImGui windows: positions and wheel steps merge, the order of events holds, a full queue removes motion and keeps a key, a button or a focus change. |
| 0016-settings-controller-keyboard | The window "Controller&Keyboard" of the ImGui windows (menu Settings, same name for the entry). It is one patch of five steps that were once separate patches. The pages are the sections Mouse and Keyboard of `settings.txt` (the list `PAGES` in `imgui_settings.c`), and a row is made from the setting's table row, so the window and the `.ini` cannot differ. An int with words is a choice, an int is a slider (a field when its range is wider than 100000), a float is a slider, and the help of the setting is the tooltip. A startup setting says that it applies at the next start, and a setting that the command line holds is disabled. A change waits in a small queue (`backend_setting_request`) and the main thread applies it in `video_poll` through the new `options_change` (`options.c`): `ini_check`, the same apply as a reload, then `ini_set`. The row `mouse_native_address` is not shown (a guest address that the launcher sets). While the pointer is over a slider or a choice, Left and Right move it by the setting's step (Shift: ten steps, Ctrl: one unit), and the window asks for the keyboard, so the game gets no arrow key. The Keyboard page has the key bindings: the 24 buttons with the keys that send them (a default key is dimmed), Bind (the next key press, taken in `video_poll` by scancode before the windows and the game see it, Esc cancels, F1 to F12, Pause and Alt are not taken), None, Default and Reset all. The window leaves the new text of `keyboard_map` for the main thread, which applies it with `options_change` (`g_keybind` belongs to that thread). A capture ends on Esc, on a loss of the focus and on a key that has no name that gives the same key back, and the bindings follow a `--keyboard_map` on the command line. Each key's release clears the buttons that its own press set. `keyboard_map_set` is split in `keybind_compile`, which the view uses too. The patch also sets the defaults: the keys A: F, B: Left Shift, X: R, Y: Space, L3: Left Ctrl, L: Q, R: E, Plus: G, Minus: M, the arrow keys for the D-pad and W, A, S, D for the left stick (ZL, ZR, R3 and the right stick have no key), the F1 help text, and `mouse_native_pitch` 500 (was 1000). The menu bar no longer comes up for a popup of another window (a combo closed at once because the bar took the focus), and it stays hidden when the program starts with the cursor outside the window (`imgui_sdl.c` gives the windows a position only when the window has the mouse focus, and no position when the cursor leaves it). The Controllers page (the section Controllers) shows the rows that every player shares (swap A/B, stick dead zone, vibration, background input, Joy-Con pairing) and the button map: for each of the 16 controls of a gamepad, a choice of the console button that it sends (None, A to Down). A button that another control sends goes to the old control of this one, so no button is lost. The map is `gamepad_map` (A and B swapped as `gamepad_swap_ab` says), "Reset to the console's layout" clears it, and the main thread saves it with `options_change` (`backend_padmap_request`). The rows of each player (`gamepad_pN_*`) are not shown, and a player's own `gamepad_pN_map` is not edited. |
| 0017-display-window | The window "Display" (menu Settings), with the tabs Display, Graphics and Performance (sections of `settings.txt`). The pages carry the window that shows them (`imgui_settings.c`), and one function draws both windows. A setting that is chosen from a short list is a combo box: the resolution scale (0.5x to 4x, with the size at 1920 x 1080 for 1x) and the anisotropic filtering (the game's, 2x to 16x); a value that is not in the list shows as custom. A startup setting that the window changed shows the saved value and "Saved. Start the game again to apply it." (`options_restart_value`, kept by `options_change`). `vsync` has three values: 0 off (immediate, else mailbox, else FIFO), 1 on (FIFO, the default), 2 on (mailbox, else FIFO). The Debug window shows the size the game renders at (scaled) and the V-sync mode. The picture's alpha is made 1 before it is presented, with a pipeline that writes only alpha (`ui.c`): the game's alpha channel made the HUD leave ghosts over the picture with mailbox and immediate (`docs/present-alpha.md`). |
| 0018-fxaa | The setting `anti_aliasing` (section Graphics, 0 off, 1 FXAA, default 0) and the pass `postfx.c`. The frame that the game presents goes through one fragment pass into an image of its own (same format and size as the render target), and the present blits from that image. The on-screen controls and the windows are drawn after the pass. The render targets and the guest memory stay as the game drew them. The shader `fxaa.frag` is a new implementation of the edge-directed blur of the FXAA whitepaper (Timothy Lottes, NVIDIA, 2009). The Display window shows the mode in the row Anti-aliasing. |
| 0019-scaling-filter | The setting `scaling_filter` (section Graphics, 0 bilinear, 1 bicubic, default 0). Bilinear is the blit of before. Bicubic draws the frame (or the anti-aliasing image) into the window image over the letterboxed rectangle with a Catmull-Rom filter over 4 x 4 texels (`shaders/bicubic.frag`, `postfx.c`). It filters in gamma space, so an sRGB frame does not ring. The Display window shows the filter in the row Scaling. FSR1 and its sharpness are next. |
